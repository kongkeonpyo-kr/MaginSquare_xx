## 1. 개요

### 1.1 제품 한 줄 정의

4×4 **부분 마방진**(빈 칸 2개)을 다룰 때, 학습자가 **임의 시행·전체 재시작**을 반복하지 않도록 **조기 판정·되돌림·시도 기준**을 제공하는 학습용 마방진 도구.

### 1.2 배경

- **도메인**: 1~16 숫자로 채운 4×4 배열. 모든 **행·열·대각선**의 합이 동일(목표 합 **34**).
- **과제**: 빈 칸 2개의 위치를 찾고, 남은 숫자 2개를 배치하여 완성된 마방진을 만든다.
- **설계 제약**: **ECB(Entity–Control–Boundary)** 패턴으로 역할을 분리한다.
- **문제 발견 방법**: Rob Fitzpatrick **Mom Test** — 솔루션 제안 없이 과거 행동만 인터뷰.

### 1.3 Mom Test vs “만들어주세요”

| 접근 | 시작점 | 산출물 |
|------|--------|--------|
| “마방진 Solver 만들어주세요” | 기능·구현 | ECB 클래스, 합 34 검증 |
| **Mom Test (본 PRD 기준)** | 과거 불편·행동 | 진짜 문제 정의 + 증거 + 실패 조건 |

본 PRD는 **Mom Test 결과를 문제 정의의 근거**로 삼고, ECB 구현은 그 문제를 해결하는 수단으로 기술한다.

## 2. 문제 정의 (Mom Test)

### 2.1 표면 문제 (잘못된 정의 — PRD 목표 아님)

> “합 34·중복 검사가 되는 4×4 마방진 Solver/연습 프로그램을 ECB로 만든다.”

- 솔루션(프로그램, Solver, ECB)이 문제 정의에 섞여 있음.
- **기능 목록만으로는** 학습자의 실제 고통(재시작 반복)을 설명하지 못함.

### 2.2 진짜 문제 (한 문장)

> 빈 칸을 채울 때 **어디부터·무엇을 시도할지 기준이 없어** 임의로 넣다가 **합이 34를 넘거나 숫자가 겹친 뒤에야** 알게 되고, 그때마다 **처음부터 다시** 하느라 같은 시행을 반복한다.

| Mom Test 축 | 본 문제에서의 의미 |
|-------------|-------------------|
| **불편** | 임의 시도 → 막힘 → 전체 재시작 |
| **비용** | 같은 시행 반복, 성공까지 “될 때까지” 반복 |
| **판정** | 합 초과·중복은 **나중에** 발견 |
| **재현** | 어디서 막혔는지·어디부터 다시할지 기록 없음 |

### 2.3 Mom Test 증거 (인터뷰 인용)

1. “합이 34가 나오도록 여러숫자를 넣어봤지”
2. “그건 임의로 진행했어”
3. “임의로 넣어보다가 합이 34가 넘으면, 또는 숫자가 겹치면 멈췄지” / “다시 처음부터”

## 3. 사용자 및 페르소나

### 3.1 주요 페르소나

| 항목 | 내용 |
|------|------|
| 역할 | 4×4 부분 마방진을 **손으로 또는 코드로** 다루는 **학습자** |
| 목표 | 빈 칸 2개를 채워 유효한 마방진 완성 |
| 현재 행동 | 합 34가 되도록 숫자를 **임의로** 넣어 봄 |
| 중단 조건 | 합 > 34 또는 숫자 **중복** |
| 중단 후 행동 | **처음부터** 다시 시도 |
| 성공 조건 | 겹치지 않는 2개 숫자 + (해당 줄) 합 34 |

### 3.2 비목표 사용자

- 마방진 이론만 탐구하고 구현·연습이 필요 없는 연구자
- n×n 일반 마방jin 생성기만 필요한 사용자 (본 버전 범위 외)

## 4. 목표 및 비목표

### 4.1 제품 목표

1. **조기 판정**: 합 초과·중복·범위 위반을 **입력 직후** 알린다.
2. **부분 되돌림**: 전체 재시작 없이 **문제 칸 또는 한 단계**만 되돌릴 수 있다.
3. **시도 기준 제공**: 빈 칸·후보 숫자·줄별 부족분 등 **다음 행동 힌트**(판정 정보)를 보여 준다.
4. **완성 검증**: 행·열·대각선 합 34 및 1~16 **한 번씩 사용** 여부를 최종 확인한다.
5. **ECB 학습**: Entity / Control / Boundary 역할 분리를 코드 구조로 연습한다.

### 4.2 비목표 (Out of Scope v1)

- AI·힌트 자동 생성 Solver의 **최적 알고리즘** 경진
- n×n 확장, 3D 마방jin
- 다중 사용자·계정·클라우드 저장
- Mom Test 인터뷰 **도구** 자체의 제품화

## 5. 도메인 규칙

### 5.1 마방jin 정의

- 격자: **4×4**
- 숫자 집합: **1~16**, 각 숫자 **정확히 1회**
- 마법 상수(목표 합): **34**
- 검증 대상: **4행 + 4열 + 2대각선** (총 10개 합)

### 5.2 부분 마방jin (초기 상태 예시)

과제 슬라이드 기준 예시 보드:

| | c1 | c2 | c3 | c4 |
|---|-----|-----|-----|-----|
| **r1** | 16 | 3 | 2 | 13 |
| **r2** | 5 | 10 | 11 | **?** |
| **r3** | 9 | 6 | **?** | 12 |
| **r4** | 4 | 15 | 14 | 1 |

- 빈 칸: **(r2,c4)**, **(r3,c3)** — `MissingFinder`가 탐지
- 정답 예: 8, 7 (구현 검증용 시드 데이터)

### 5.3 완성 조건 (`SolveResult`)

- 모든 칸이 채워짐
- 10개 합 == 34
- 1~16 중복 없음
- `SquareValidator`가 **Pass** 반환

## 6. 아키텍처 (ECB)

### 6.1 역할 분리

```
┌─────────────────────────────────────────────────────────┐
│  <<Boundary>>                                           │
│  GridUI · InputHandler · ResultDisplay                  │
│  (표시·입력·결과 메시지 — 판정 로직 없음)                  │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  <<Control>>                                            │
│  MissingFinder · SquareValidator · Solver               │
│  (빈 칸 탐지·규칙 검증·해 탐색/완성 흐름 조율)              │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  <<Entity>>                                             │
│  MagicSquare · Cell · SolveResult                       │
│  (4×4 상태·칸 값/좌표/상태·풀이 결과)                      │
└─────────────────────────────────────────────────────────┘
```

### 6.2 컴포넌트 책임

| 계층 | 컴포넌트 | 책임 |
|------|----------|------|
| **Entity** | `MagicSquare` | 4×4 그리드, 1~16 사용 여부, 불변 규칙 데이터 |
| **Entity** | `Cell` | 값, (row,col), empty/filled/invalid 상태 |
| **Entity** | `SolveResult` | success/fail, 실패 코드, 완성 보드 스냅샷 |
| **Control** | `MissingFinder` | 빈 칸 좌표 목록 반환 |
| **Control** | `SquareValidator` | 행·열·대각선 합, 중복, 범위, 합 초과 **조기** 판정 |
| **Control** | `Solver` | 후보 배치·백트래킹 또는 규칙 기반 완성 (Control 내부) |
| **Boundary** | `GridUI` | 격자 시각화, 빈 칸·오류 칸 강조 |
| **Boundary** | `InputHandler` | 사용자 숫자 입력, undo 한 단계 요청 |
| **Boundary** | `ResultDisplay` | 판정 메시지, 완성/실패 요약 |

### 6.3 Mom Test → ECB 매핑

| 진짜 문제 | ECB 대응 |
|-----------|----------|
| 시도 기준 없음 | `MissingFinder` + 줄별 **부족분(34−현재합)** 표시 (`ResultDisplay`) |
| 늦은 판정 | `SquareValidator` — 입력 **직후** 중복·합 초과·범위 검사 |
| 처음부터 재시작 | `InputHandler` + Entity 상태 — **한 칸 undo** / 부분 보드 유지 |
| 완성 여부 불확실 | `SquareValidator` 전체 검증 + `SolveResult` |

## 8. 문제 인식 포인트 (실패 조건)

과제 목표: **최소 3개**. Mom Test·도메인 규칙에서 도출.

| 코드 | 조건 | 사용자에게 보여 줄 메시지 (예) | 검증 주체 |
|------|------|-------------------------------|-----------|
| **E-DUP** | 1~16 **중복** 입력 | “이미 사용한 숫자입니다.” | `SquareValidator` |
| **E-OVER** | 해당 행 또는 열 **합 > 34** | “이 줄의 합이 34를 초과했습니다.” | `SquareValidator` |
| **E-RANGE** | 1~16 **범위 밖** | “1~16 사이 숫자만 입력할 수 있습니다.” | `SquareValidator` |
| **E-INCOMPLETE** | 빈 칸 남은 채 “완료” 시도 | “아직 채우지 않은 칸이 있습니다.” | `MissingFinder` + Validator |
| **E-INVALID** | 전 칸 채웠으나 10개 합 ≠ 34 또는 숫자 집합 불일치 | “마방jin 조건을 만족하지 않습니다.” | `SquareValidator` |
| **E-UNDO** | (UX) 전체 초기화 대신 **부분 undo** 권장 | “이 칸만 되돌릴까요?” | `InputHandler` |

**P0 필수 3종**: `E-DUP`, `E-OVER`, `E-INVALID` (또는 `E-RANGE`).

## 9. 사용자 시나리오

### 9.1 Happy Path

1. 학습자가 부분 마방jin 보드를 연다.
2. 빈 칸 2곳과 각 줄 **남은 합**을 확인한다.
3. 한 빈 칸에 후보 숫자를 입력한다.
4. `SquareValidator`가 중복·합 초과 없음을 확인한다.
5. 두 번째 빈 칸 입력 후 전체 검증 **Pass** → `ResultDisplay`에 완성 메시지.

### 9.2 Mom Test 기반 Failure Path

1. 학습자가 **임의**로 숫자를 입력한다.
2. **E-OVER** 또는 **E-DUP** 발생 → 해당 칸 강조.
3. 학습자가 **undo 1회**로 해당 칸만 되돌린다 (처음부터 X).
4. **남은 합**을 참고해 다른 후보를 시도한다.
5. (P1) `Solver`로 해 존재 여부 확인 후 학습.
