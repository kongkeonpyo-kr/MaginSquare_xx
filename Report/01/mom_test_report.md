## 1. 목적

솔루션(프로그램·Solver·TDD) 제안 없이, 학습자의 **과거 행동**만 수집하여 진짜 문제를 정의한다.

## 2. 인터뷰 규칙

1. 한 번에 질문 1개
2. 금지: “만들면 좋겠어?”, “이 기능 필요해?”, “TDD 하면 어때?”
3. 허용: “마지막으로 ~했을 때”, “몇 분 걸렸어?”, “뭐 때문에 포기했어?”
4. 모호하면 추궁 1개
5. 솔루션 언급 시 “그건 나중” — 불편으로 되돌리기

## 3. Q&A 기록

| # | 질문 | 답변 (과거 사실) |
|---|------|------------------|
| 1 | 마지막으로 빈 칸 두 개 채울 때 가장 먼저 한 일? | 합이 34가 나오도록 여러 숫자를 넣어봤다 |
| 1-F | 첫 번째로 손댄 줄(칸)? | 임의로 진행했다 |

## 4. Mom Test 워크북

### 인터뷰 답변 (과거 사실)

- 합 34가 되도록 여러 숫자를 **임의로** 넣어 봄
- **합 > 34** 또는 **숫자 겹침** 시 멈춤
- 멈춘 뒤 **처음부터** 다시 시도
- 반복 끝에 겹치지 않는 2개 숫자·합 34를 찾음
- 재시도 횟수는 “될 때까지” — 정량 기록 없음

### 표면 문제 (금지 — 솔루션 섞임)

> “합 34·중복 검사가 되는 4×4 마방진 Solver/연습 프로그램을 ECB로 만든다.”

### 진짜 문제 (한 문장)

> 빈 칸을 채울 때 **어디부터·무엇을 시도할지 기준이 없어** 임의로 넣다가 **합이 34를 넘거나 숫자가 겹친 뒤에야** 알게 되고, 그때마다 **처음부터 다시** 하느라 같은 시행을 반복한다.

### Mom Test 증거 3줄 (인용)

1. “합이 34가 나오도록 여러숫자를 넣어봤지”
2. “그건 임의로 진행했어”
3. “임의로 넣어보다가 합이 34가 넘으면 , 또는 숫자가 겹치면 멈췄지” / “다시 처음부터”

## 5. Mom Test 축 분석

| 축 | 관찰 |
|----|------|
| **불편** | 임의 시도 → 막힘 → 전체 재시작 |
| **비용** | “될 때까지” 반복, 횟수 미인지 |
| **판정** | 합 초과·중복을 **사후**에야 인지 |
| **재현** | 어디서 막혔는지·부분 성과 보존 없음 |

## 6. PRD·설계 연결

| 진짜 문제 | 후속 설계 방향 |
|-----------|----------------|
| 시도 기준 없음 | 빈 칸·줄별 남은 합 표시 |
| 늦은 판정 | 입력 직후 E001~E003 (범위·중복·합 초과) |
| 처음부터 재시작 | 부분 undo, 전체 초기화 회피 |
